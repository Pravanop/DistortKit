# DistortKit

An open-source Python toolkit for analyzing crystal distortions, in the spirit of existing symmetry-mode analysis packages (DistortKit is an independent endeavour not affiliated to any previous efforts). Give it a
high-symmetry **parent** structure and a low-symmetry **child** and it reports, with no manual alignment,

* the space group of both (number and Hermann-Mauguin symbol),
* the **symmetry-adapted displacement modes** of the child, per wavevector, with standard irrep labels
  (R4+, GM4-, X5+ ...), amplitudes, and the isotropy subgroup / child space group each mode leads to,
* the lattice **strain** (rigid rotation removed) and its decomposition into strain irreps,
* diagnostics that say when something looks wrong,
* when the two structures are **not** group-subgroup related: why not, and a **common parent** that both are distortions of
  (`relate`), and
* how much of a distortion each symmetry explains, and which modes **drive** which (`explain`), and
* the **polynomial invariants** of the modes: the allowed Landau terms and mode-mode couplings (`invariants`).

It can also generate distorted child structures for any irrep and isotropy subgroup, and works from POSCAR/CIF
files, including a POSCAR that carries **no symmetry information** (the parent is then symmetrised
with pymatgen's `SpacegroupAnalyzer`, saved as a CIF with explicit operations, and used automatically).

It is **not** a port of any ISOTROPY code. The space-group and Wyckoff tables are open data generated by
`tools/build_tables.py` and verified against ISOTROPY's (below); only the *names* of irreps (X5+, R4+ ...) come from two
ISOTROPY data files, which are bundled with attribution (see [NOTICE](NOTICE)) and are optional: without them
the analysis works and modes are instead given generic names called `irrep5` etc.

## Install

```bash
pip install git+https://github.com/Pravanop/DistortKit.git
distortkit --help
```

That one command installs everything: the analysis (numpy), automatic symmetry assignment for a POSCAR without symmetry
information (pymatgen), and GIF animations (matplotlib, Pillow). Python 3.9 or newer. From a clone instead:
`git clone https://github.com/Pravanop/DistortKit && cd DistortKit && pip install .` (add `-e` to work on the code).
`python3 -m distortkit` works the same as the `distortkit` command.

To keep the heavy packages in a separate environment, point `DISTORTKIT_PYTHON` at that interpreter; DistortKit then runs
the symmetrisation and rendering helpers in it.

## Quick start

```bash
# after `pip install` the command is `distortkit`; the examples below use python3 -m distortkit, which is the same

# one command, from files (JSON, POSCAR/CONTCAR, or CIF with explicit symmetry operations)
python3 -m distortkit compare parent.vasp child.vasp

# add --atoms for the displacement of every atom and each mode's share of it
python3 -m distortkit compare examples/hfo2/Pbcm.cif examples/hfo2/Pca21.cif --atoms

# are two structures group-subgroup related? why not? is there a common parent?
python3 -m distortkit relate examples/hfo2/Pbcm.cif examples/hfo2/Pca21.cif
python3 -m distortkit relate examples/hfo2/Pca21.cif examples/hfo2/Pbca.cif --parent examples/hfo2/fluorite_Fm-3m.cif

# what does each symmetry explain, and which modes drive which (reads the analysis `compare` saved)
python3 -m distortkit explain examples/hfo2/fluorite_to_Pca21_analysis.json

# the allowed Landau terms and couplings of those modes
python3 -m distortkit invariants examples/hfo2/fluorite_to_Pca21_analysis.json

# pieces
python3 -m distortkit check      parent.vasp                  # sanity checks + space group vs tolerance
python3 -m distortkit symmetrize parent.vasp                  # -> parent_symmetrized.cif
python3 -m distortkit modes      parent.json --k 1/2 1/2 1/2  # irreps (with labels) at a k-point
python3 -m distortkit isotropy   parent.json --k 1/2 1/2 1/2 --irrep 5   # subgroups, child space groups
python3 -m distortkit distort    parent.json --k 1/2 1/2 1/2 --irrep 5 --subgroup 1 --amplitude 0.5 --format cif
```

tables, in the standard setting; checked against the FINDSYM labels in `examples/hfo2/`) with the amplitude each mode
carries on each site, which is how ISODISTORT organises its mode table; `--atoms` adds the per-atom table. Example
(HfO2, Pbcm -> Pca2_1):

```

        GM2- 0.4779   GM1+ 0.0631

```

The per-atom contributions of all modes add up to each atom's displacement (tested), and a mode's amplitude is the
root-sum-square of its site amplitudes.

Python:

```python
from distortkit import analyze           # the whole pipeline
res = analyze("parent.vasp", "child.vasp")  # symmetrises, checks, compares
print(res.report())                          # res.comparison has the numbers; res.ok / res.findings the checks

from distortkit import ModeAnalysis, Structure
ma = ModeAnalysis(Structure.from_json("examples/srtio3_cubic.json"), (0.5, 0.5, 0.5))
ma.space_group()                             # Pm-3m (#221) with the setting transformation
ma.irrep_labels()                            # {irrep index: IrrepLabel}
```

## Use it from Python

Everything the command line does is a function call: the CLI is a thin wrapper. The commands and their Python entry points:

| command | Python |
|---|---|
| `compare` | `distortkit.analyze(parent_file, child_file)` (files) or `distortkit.compare(parent, child)` (`Structure` objects) |
| `show`, `freeze` | `distortkit.freeze.Freezer` (`build`, `legend`), `freeze.run`, `freeze.run_mcif`, `animate.run_gif` |
| `relate` | `distortkit.relate.relate(a, b, common=True, ...)` |
| `explain` | `distortkit.explain.report`, `.ladder`, `.cascade` |
| `invariants` | `distortkit.invariants.compute` |
| `modes`, `isotropy`, `distort` | `distortkit.ModeAnalysis` (irreps at one k-point) |
| `phonons` | `distortkit.phonons.PhononSymmetry`, `.analyze_band_yaml`, `.read_band_yaml` |
| `symmetrize`, `check` | `distortkit.symmetrize`, `distortkit.checks` |

```python
from fractions import Fraction
from distortkit import analyze, compare, read_structure, ModeAnalysis, Structure
from distortkit.freeze import Freezer
from distortkit.relate import relate
from distortkit import explain, invariants

H = "examples/hfo2/"

# 1. parent + child files -> the full analysis (what `distortkit compare` prints)
res = analyze(H + "Pbcm.cif", H + "Pca21.cif")         # POSCAR / CIF / JSON; a parent without symmetry info is symmetrised
print(res.report(min_amp=0.05))
cmp = res.comparison                                    # the result object
print(cmp.parent_sg.label(), "->", cmp.child_sg.label())          # Pbcm (#57) -> Pca2_1 (#29)
for m in cmp.modes:                                     # symmetry-adapted modes, largest first
    name = m.label.text if m.label is not None and m.label.candidates else f"irrep{m.irrep.index}"
    print(m.id, name, ",".join(map(str, m.k)), f"{m.amplitude:.4f} A")      # m1 GM2- 0,0,0 1.1844 A

# 2. the same from Structure objects; save the analysis for the steps below
parent, child = read_structure(H + "Pbcm.cif"), read_structure(H + "Pca21.cif")
cmp = compare(parent, child)                            # strain, modes, atoms: cmp.strain, cmp.modes, cmp.atom_rows() ...
cmp.save("analysis.json")

# 3. build structures along the distortion
fz = Freezer.load("analysis.json")
print(fz.legend())                                      # the modes, sites and atoms you can select
half, info = fz.build(["GM2-*0.5"])                     # polar mode at half the amplitude found in the child
with open("POSCAR_half", "w") as fh:
    fh.write(half.to_poscar())                          # or half.to_cif()

# 4. how are two structures related? (group-subgroup either way, why not, a common parent)
rel = relate(parent, child, names=("Pbcm", "Pca21"))
print(rel.verdict, rel.ab.ops.summary())                # a>b: every operation of the child is an operation of the parent ...

# 5. what does each symmetry explain, which modes drive which, which couplings are allowed
fz = Freezer.load(H + "fluorite_to_Pca21_analysis.json")
text, ladder, cascade = explain.report(fz)
print([(lv.driver_name, lv.sg.label()) for lv in cascade.levels])   # [('X5+', 'Pbca (#61)'), ('X2-', 'Pca2_1 (#29)')]
inv = invariants.compute(fz, ["X5+", "X2-", "GM4-"])
print([inv.term_name(t.degrees) for t in inv.terms if sum(t.degrees) == 3 and t.n_new])   # ['X5+ X2- GM4-', 'X5+^3']

# 6. low level: the irreps at one k-point of a parent, and a child frozen from one of them
parent = Structure.from_json("examples/srtio3_cubic.json")
ma = ModeAnalysis(parent, (Fraction(1, 2),) * 3)        # the R point
print(ma.space_group().label(), [(ir.index, ir.dim) for ir in ma.irreps])
ir = ma.irreps[4]                                       # the 3-dimensional oxygen tilt irrep (index 5 in `distortkit modes`)
iso = ma.isotropy_subgroups(ir)[0]                      # first isotropy subgroup (order-parameter direction iso.opd)
tilted = ma.child_structure(ma.displacement(ir, iso.opd), 0.5)      # amplitude in Angstrom
print(iso.point_group, ma.child_space_group(iso).label())           # 4/mmm I4/mcm (#140)
```

The result objects hold plain numpy arrays and dataclasses (displacements per atom, per site and per mode, strain, labels,
subgroups), so they plug into your own scripts; `cmp.to_dict()` is the JSON the CLI prints with `--json`.

## Building structures along the distortion (freeze modes and atoms)

You can only choose what to freeze after reading the analysis, so this is a second step. `compare` writes an
analysis file (`<child>_analysis.json`, next to the child; `--save PATH` / `--no-save`) holding every mode's
displacement of every atom, the sites, atom labels and strain. Then:

```bash
python3 -m distortkit show   Pca21_analysis.json          # the legend: modes, atoms, Wyckoff sites, how to select
python3 -m distortkit freeze Pca21_analysis.json [what to freeze] [how far] [format]
```

**Choosing what to freeze** (the names are the ones in the report; `show` prints them):

| you want | option |
|---|---|
| one mode | `--modes GM2-` (or its id, `--modes m1`) |
| two (or more) modes together | `--modes GM2-,GM1+` |
| every mode | `--modes all` (`rest` = displacement in no listed mode, `child` = all + rest = the child itself) |
| certain atoms only | `--atoms Hf` / `Hf1,O3` / `O1-O4` / `O@4c` (species at a Wyckoff site) / `@4d` / `s2` (site number) |
| leave atoms out | `--not-atoms O5` |
| certain atoms *within* a mode | `--part 'GM2-:Hf'` |
| different atoms or amplitudes per mode | `--part 'GM2-:Hf' --part 'GM1+:O*0.5'` |
| certain atoms, several modes | `--modes GM2-,GM1+ --atoms Hf` |

A part is `MODE[:ATOMS][*SCALE | =AMPLITUDE]`: `*0.5` is half the amplitude found in the child (negative reverses the
mode: the opposite domain), `=0.8` sets the part's root-sum-square amplitude to 0.8 A.

**How far: the final amplitude and how many structures.** `--amplitude 1.0 --n 5` builds 5 structures evenly spaced from
`--start` (default 0 = the parent) to a final amplitude of 1.0 A. The amplitude is the root-sum-square size (A) of whatever
you selected (the same quantity the report calls amplitude; for several modes or parts the ratio between them is kept).
Give `--start -1.0 --amplitude 1.0 --n 9` for a double-well scan through the parent into the opposite domain. In a
terminal, if you leave these out, `freeze` asks (showing the amplitude found in the child as the default); in scripts it
builds one structure at the amplitude found in the child (`--amplitude found`). Advanced: `--scales -1,0,0.5,1` takes
fractions of the child's amplitude instead. `--cell parent` (default) keeps the undistorted lattice, `--cell child` strains
it by the child's strain times the same fraction.

**Sets of structures in one go:** `--each mode|site|species|atom`, `--pairs`, `--cumulative` (m1, m1+m2, ...),
`--combinations [--max-size 2]`; these combine with `--modes` and `--atoms` to restrict them.

**Output:** `--format poscar|cif|both` into `--outdir` (default: `frozen/` next to the analysis). The CIFs carry the
detected symmetry operations, so they can go straight back into `compare`. A `manifest.txt`/`manifest.json` lists every
file with its recipe, scale, displacement size and **space group** (e.g. the polar mode alone gives Pca2_1, the
totally symmetric one keeps Pbcm). Atoms are written in the legend's order (species grouped), so files can be compared
atom by atom.

```bash
python3 -m distortkit freeze an.json --each mode                     # one structure per mode
python3 -m distortkit freeze an.json --modes all --atoms Hf          # certain atoms, all modes
python3 -m distortkit freeze an.json --part 'GM2-:Hf' --part 'GM1+:O*0.5'
python3 -m distortkit freeze an.json --modes GM2- --start -0.8 --amplitude 0.8 --n 9 --format both
python3 -m distortkit freeze an.json --each site                     # all modes, one Wyckoff site at a time
```

Python: `fz = Freezer.load("an.json"); structure, info = fz.build(["GM2-:Hf", "GM1+:O*0.5"], scale=0.5)`, or `freeze.run(fz, freeze.enumerate_recipes(fz, modes=["GM2-"]), amplitude=1.0, n=5, outdir="out")`.

## Seeing a mode in VESTA (arrows)

`show --mcif` writes **mCIF files that carry the atomic displacements as vectors**, so opening one in VESTA draws an
arrow on every atom showing how it moves in that mode. (mCIF is only the carrier: VESTA draws "magnetic moments" as
arrows; nothing magnetic is implied.) The atoms are at the **parent** positions in the child's supercell, so a mode at
k != 0 shows its whole modulation. Atoms with no displacement in the selection get no arrow.

```bash
python3 -m distortkit show an.json --mcif                          # one file per mode
python3 -m distortkit show an.json --mcif --modes GM2-             # a single mode
python3 -m distortkit show an.json --mcif --modes GM2-,GM1+        # coupled modes (their sum, as in the child)
python3 -m distortkit show an.json --mcif --part 'GM2-:Hf'         # certain atoms within a mode
python3 -m distortkit show an.json --mcif --part 'GM2-:Hf' --part 'GM1+:O*0.5'
python3 -m distortkit show an.json --mcif --modes GM2- --amplitude 0.5   # rescale the amplitude (negative reverses)
python3 -m distortkit show an.json --mcif --each site | --pairs | --cumulative   # sets, as in `freeze`
```

The selections use the same words as `freeze`. Files go to `arrows/` next to the analysis file (`--outdir`); the folder
also gets `arrows_manifest.txt` listing each file, its selection, amplitude, arrow count and longest arrow. Vectors are in
Angstrom (`--arrow-scale N` multiplies them); in VESTA change the arrow length and colour under Properties > Vectors.
The vectors are stored as components along the unit vectors of the supercell axes
(`_atom_site_moment.crystalaxis_x/y/z`), which is exact for non-orthogonal cells too (tested with a hexagonal cell). Examples
for the HfO2 pathway are in `examples/hfo2/arrows/`.

## Animations (GIF)

`show --gif` writes an animated GIF of the atoms moving in a mode (or any selection), using the same selections as
`freeze` and the arrow files. The atoms oscillate about their **parent** positions, 0 -> +max -> 0 -> -max -> 0, where
**max is a fraction or percentage of the amplitude found in the child** (100% = the child's own distortion; 50% = half of it).
The picture shows element-coloured atoms, bonds (half-bonds leave the cell), the supercell outline, and a caption with the
selection and the current percentage.

```bash
python3 -m distortkit show an.json --gif --modes GM2- --fraction 100%        # the polar mode at full amplitude
python3 -m distortkit show an.json --gif --modes GM2-,GM1+ --fraction 50%    # coupled modes, half amplitude
python3 -m distortkit show an.json --gif --part 'GM2-:Hf' --fraction 1       # certain atoms within a mode
python3 -m distortkit show an.json --gif --each mode --fraction 75% --view b --arrows
python3 -m distortkit show an.json --gif --modes GM2- --amplitude 0.4        # largest excursion in Angstrom instead
```

Options: `--fraction 50%` or `0.5` (asked for at a terminal if omitted; `--amplitude A` in Angstrom instead), `--frames N`
(per cycle, default 24), `--fps`, `--oneway` (parent -> max -> parent, no negative half), `--view iso|a|b|c|-a|-b|-c` or
`--elev/--azim`, `--arrows` (displacement arrows), `--no-bonds`, `--size` pixels, `--loops` (0 = forever), `--outdir`
(default `animations/` next to the analysis file) and `--prefix`. An `animations_manifest.txt` lists the files. Look down
an axis perpendicular to the atomic motion (e.g. `--view b` for motion along c) to see it best.

Rendering uses matplotlib and Pillow, which are installed with DistortKit; they can also live in a separate environment
(`~/.venvs/distortkit`, found automatically; or set `DISTORTKIT_PYTHON`). Examples: `examples/hfo2/animations/`.

## Phonon viewer (web)

`viewer/` is a browser app for looking at phonon modes: open a phonopy `band.yaml` (or a phononwebsite `.json`), click a point
on the band structure, and the atoms move. It runs entirely in the browser (nothing is uploaded), and is published at
<https://pravanop.github.io/DistortKit/>.

* views along a, b, c, a\*, b\*, c\*, x, y, z or any `[uvw]` / `(hkl)`, with an axes gizmo that turns with the crystal;
* supercells fitted to the wavevector, displacement arrows, bonds, element colours;
* export to PNG (transparent background if you like), GIF, MP4/WebM video and XYZ, plus the band plot as PNG;
* imaginary (unstable) modes are flagged, and a per-mode list shows each mode's species composition;
* a **Symmetry** section that, on request and in your browser, works out each mode's irrep and the child space group it leads to (the `phonons` command below, run locally with Python in the page; nothing is uploaded).

To run it locally: `python3 viewer/tools/serve.py` and open <http://localhost:8123>. Its conventions (phase, mass weighting),
tests and limits are in [viewer/README.md](viewer/README.md). It is independent of the analysis commands above for now; showing
DistortKit's symmetry modes in it is planned. The idea and part of the data formats come from
[phononwebsite](https://henriquemiranda.github.io/phononwebsite/) (H. Miranda); this viewer is separate and not affiliated with it.

## When the structures are not group-subgroup related (`relate`)

`relate A B` says how two structures (any setting, any atom order) are related, and what to do when they are not.

```bash
python3 -m distortkit relate A.cif B.cif                         # diagnosis only
python3 -m distortkit relate A.cif B.cif --common                # + search for a common parent, compare both against it
python3 -m distortkit relate A.cif B.cif --parent aristotype.cif # + use this structure as a candidate common parent
```

**1. Diagnosis.** Each direction (A as the parent of B, B of A) is tried with progressively looser strain and
displacement limits. It reports: different composition; atom counts that are not an integer multiple; no supercell with
that lattice; atoms that cannot be paired within the limit; or the structures overlay but are **not nested**. That last
check is exact and operation by operation (`subgroup.py`): the child is laid on the parent's own lattice (strain and
rotation removed), its symmetry operations are found there, and each must be one of the parent's (rotation equal,
translation equal modulo the lattice). A point-group comparison cannot tell Pbcm from Pbca (both mmm); this can.
Operations the parent lacks are listed as `rotation` (the child has symmetry the parent does not: the real parent has
more symmetry, or they are siblings) or `translation` (right rotation, wrong glide/screw/origin). `compare` runs the same
check and raises the error `not-subgroup-ops`; among overlays of similar quality it uses the tightest one that
*respects the parent's symmetry*, not merely the lowest rms.

```
Pbcm as parent of Pca21: yes. 1 parent cell(s); rms displacement 0.359 A ...; every operation of the child is an operation of the parent (4 of 8; index 2)
Pca21 as parent of Pbca: no. The structures overlay (2 parent cell(s); rms 0.506 A, max 1.116 A) but 4 operation(s) of the child are NOT operations of the parent
verdict: no group-subgroup relation either way.
```

**2. A common parent (siblings).** Two structures that are both distortions of a third (a perovskite with an R-point
tilt and another with a polar zone-centre mode; HfO2 Pca2_1 and Pbca, both from fluorite). `--common` looks for it
two ways and keeps a candidate only if **both** structures are subgroup-distortions of it (the exact check above):

* *pseudo-symmetry* (`pseudo.py`): the largest **group** of operations each structure obeys approximately, at tolerances
  0.05-0.5 A, built so that every product of operations is re-checked against the atoms (a loose tolerance gives the
  largest consistent group, not a heap of unrelated operations); the structure is then idealised with it and reduced
  to its primitive cell. `--max-tol` extends the range, `--species-tol O=3` lets the anions move more.
* `--parent FILE` (repeatable): your own candidate, e.g. the aristotype of the family.

Among valid candidates it uses the highest-symmetry one needing about the smallest displacement (`--pick N` takes
another from the list). Both structures are then decomposed against it with the same irrep convention, and the modes are
tabulated side by side: which irreps carry displacement in both, which only in one.

```
parent used: Pm-3m (#221), 5 atoms per primitive cell (pseudo-symmetry of tilt at 0.3 A)
  wavevector      irrep          dim            tilt           polar   present in
  (1/2,1/2,1/2)   R4+              3          0.3536          0.0000   only tilt
  (0,0,0)         GM4-             3          0.0000          0.0746   only polar
```

Real output for the HfO2 pair against fluorite: `examples/hfo2/relations/`. There Pca2_1 is X2- + X5+ + GM4- (+ X5-, X3-)
and Pbca shares X5+ but has large modes at (0,1/4,0) and W that Pca2_1 lacks.

**What this cannot do.** The pseudo-symmetry search finds parents reachable by displacements of up to about half an
interatomic distance. The HfO2 phases are 0.5-1.2 A from fluorite, too far: there the search finds nothing (or, with
loose `--species-tol`, a wrong group) and the output says to pass `--parent`. Pbcm is *not* a subgroup of fluorite
(the check says so: some of its operations differ from fluorite's by a translation of 0.85 A). Pbcm and fluorite are
both parents of Pca2_1 but neither is nested in the other. Reconstructive
transitions (no common parent with small displacements) are outside this tool.

## How much does a symmetry explain, and which mode drives which (`explain`)

`explain analysis.json` (the file `compare` saved) lets the parent's operations act on the child's displacement field:
an operation sends each atom to an equivalent parent site and rotates its displacement. Averaging over a group H keeps
exactly the part of the distortion H allows; the rest breaks H.

1. **Symmetry ladder.** For each tolerance, the largest group the *whole* displacement pattern obeys to within it, its
   space group, the share of the squared displacement it explains, and the remainder (rms per atom and total) with
   the modes that carry it. A clean child shows its own group at 100%. A relaxed or noisy one shows a symmetric core
   and a small remainder: e.g. P1 at 1e-4 A, then 98.6% by Ima2, then 95.3% by I4/mcm, then at 0.4 A the parent itself
   explaining nothing. Mode-by-mode, the lines "breaking Ima2: irrep2 (m2) 0.020 of 0.056 A" say where the extra distortion is.
2. **Mode roles (cascade).** The largest mode is the **primary**. The operations that leave it unchanged form its
   isotropy subgroup H1; modes whose displacement H1 permits are **allowed** by it (shown with the structure's
   symmetry at that level). A mode H1 does not permit is **independent**: it needs its own order parameter, which cuts the
   symmetry further, and the next modes become allowed once both are frozen. The cascade ends at the child's group.
   `--primary X2-,X5+` sets the drivers yourself. Modes allowed by the full group (e.g. GM1+) are listed as fully symmetric.

```
level 1: m1 X5+ (1.2925 A) is PRIMARY               symmetry kept: Pbca (#61)
level 2: m2 X2- (0.9744 A) is INDEPENDENT (not allowed by X5+ alone)     symmetry kept: Pca2_1 (#29)
   allowed once X5+ + X2- is frozen: m3 GM4- (0.4463 A), m4 X5- (0.4035 A), m5 X3- (0.1702 A)
```
(`--primary X2-` instead gives Fm-3m -> P4_2/nmc -> Pca2_1.) "Allowed" means the symmetry permits the mode and its
coupling, not that the coupling is large. Modes below `--min-amp` (default 0.02 A) are ignored, which keeps noise out of
the cascade. An operation counts as leaving a mode unchanged if it moves no atom by more than `--opd-tol` (5%) of the mode's
largest displacement; `--allowed-share` (95%) is how much of a mode's squared amplitude a group must permit. Only parent
operations that map the child's supercell lattice onto itself take part (others carry the child into another domain).
`--json` gives the tables for scripts.

## Landau invariants and couplings (`invariants`)

`invariants analysis.json` answers "which free-energy terms does the symmetry allow among these modes?": the polynomial
invariants of the parent's space group in the order-parameter components. It is the equivalent of ISOTROPY's INVARIANTS,
but for the modes found in *your* child.

```bash
python3 -m distortkit invariants analysis.json                     # every mode above 0.02 A, up to degree 3
python3 -m distortkit invariants analysis.json --modes X5+,X2-,GM4- --degree 4
python3 -m distortkit invariants analysis.json --all --json        # every term and coupling, for scripts
```

Each mode's order-parameter space is the real irrep space it lives in: the orbit of its displacement field under the
parent group, on the smallest supercell that holds every symmetry image of the child (so all arms of the star are
present and the translations act as phases: momentum conservation comes out by itself). Invariants split by
*multidegree* (how many components of each mode a term has), which does not depend on the choice of basis, so that is
how they are reported:

1. **Allowed terms**: for each multidegree the number of independent invariants and how many are *new* (not products
   of lower-degree ones): `R4+^2`, `R4+^4`, `X5+ X2- GM4-`. For the R-point tilt of the perovskite this gives
   1 / 2 (1 new) / 3 (1 new) invariants at degrees 2 / 4 / 6, the generators of degrees 2, 4, 6 of the cubic group;
   the counts are checked against the Molien average of the group in the tests.
2. **Couplings linear in a mode**: for each mode s, the force every allowed term that is linear in s exerts on it when the
   other modes sit at their measured amplitudes, and how much of the *measured direction* of s lies in the span of
   those forces. 100% means the coupling induces exactly the direction found; a force that vanishes means the term is
   allowed but does nothing there; a low match means other terms of the mode set its direction.

```
GM4- <- X5+ X2-   (degree 3, 1 invariant(s)): induces exactly the measured direction (100% match)
X5+  <- X2- GM4-  (degree 3, 1 invariant(s)): pushes it only 59% along the measured direction (not fully induced ...)
```

In the fluorite -> Pca2_1 example this is the improper coupling: the trilinear term `X5+ X2- GM4-` exists (as do
`X5+ X5- X3-`, `X5+ GM4- X5-` ... and `X5+^3`; there is no `X2-^3` and no `X5+^2 X2-`), and every secondary mode (X2-,
GM4-, X5-, X3-) is induced by the others in exactly the measured direction while X5+ is not. This agrees with the
`explain` cascade (the modes it calls "allowed" all have an active coupling). A trilinear term is symmetric in its
modes, so it says each is permitted by the other two, not which one drives. Free-energy coefficients are free: nothing
here says how large a term is, whether the transition is first or second order, or which mode goes soft. Strain,
gradient terms and external fields are not included. Examples: `examples/hfo2/relations/`.

## Symmetry of phonons (`phonons`)

Which irrep does a phonon belong to, and what symmetry does freezing it in lead to? Give `phonons` a phonopy `band.yaml`
(written with `EIGENVECTORS = .TRUE.`); for every q-point and band it reports the irrep of the parent space group, the isotropy
subgroup (child space group) that the mode's direction fits, and, per irrep, every child symmetry it can lead to.

```bash
python3 -m distortkit phonons examples/hfo2/fluorite_springs_band.yaml --qpoints 5     # the X point
```

```
q-point 1 (X): (1/2, 0, 1/2)   star of k=(0, 1/2, 1/2), 4-cell supercell
  band   freq (THz)  irrep        dim  child symmetry (direction of this mode)
     1      -3.027  X2-            3  P4_2/nmc (#137)   (a,0,0)
     2       1.716  X5-            6  Pmmn (#59)   (a,0,0,0,0,0)  [adapted]
     4       5.538  X3-            3  P4/nmm (#129)   (a,0,0)
     5       7.207  X1+            3  P4/mmm (#123)   (a,-0.081a,0)
     6       7.518  X5+            6  P2_1/c (#14)   any direction in a 2-parameter subspace  [adapted]
```

The first line is the soft mode of cubic hafnia: X2- has an imaginary frequency, and freezing it in gives the tetragonal P4_2/nmc phase.

(excerpt; the example is a spring model of fluorite HfO2, not DFT: the right geometry and symmetry, and a soft X2- mode tuned to about -3 THz, but not real frequencies.)

* **The eigenvector is analysed as a displacement pattern.** It is turned into a real displacement field on the supercell
  `ModeAnalysis` builds for the star of q and projected onto the irreps, exactly as `compare` does for a child structure; the
  conventions (phonopy's phase includes the atomic positions; eigenvectors are divided by sqrt(mass)) are the ones used by the
  [web viewer](#phonon-viewer-web).
* **Degenerate levels are adapted.** The eigenvectors a phonon code writes for a degenerate level are an arbitrary mixture (a level can
  even hold two different irreps), which says nothing about symmetry. `[adapted]` marks bands rotated within their level
  into one irrep each, along the irrep's own axes where possible (the X5 doublets above); the rotated eigenvector is saved in the JSON.
* **Checked independently.** Each predicted child space group is compared with what spglib finds for the structure displaced by that
  mode (`tests/test_phonons.py`); all nine bands at X agree. At Γ the acoustic modes, which are rigid translations, are reported as changing nothing (spglib confirms the structure keeps Fm-3m).
* **Limits.** Only q-points whose star fits in `--max-cells` primitive cells (default 16) are analysed; the others are listed as
  skipped, with the reason (W of an fcc cell needs 32). Irreps larger than `--max-dim` (default 6) are assigned to modes but their
  subgroups are not enumerated, because that can take minutes. For a degenerate multiplet the direction is only defined up to the
  multiplet, so the list of subgroups of the irrep is the answer; which one is realised depends on which combination condenses.
  Stable modes do not condense by themselves; only unstable ones (imaginary frequency) drive a transition.
* **Known gap.** `spacegroup.identify` cannot yet name the trigonal (R3m, (a,a,a)-type) child of a cubic F-lattice parent; those
  subgroups are listed as "unidentified" with their point group, and irrep labels at the zone centre and L of such parents are
  missing for the same reason.

The JSON (`--out`, default `<bandfile>_symmetry.json`) has the same content as plain data (stars with their irreps and subgroups; per
q-point and band the irrep, weights, direction, subgroup and, for adapted bands, the eigenvector), ready for a viewer to load: the [web viewer](#phonon-viewer-web) can open it, but it does not need to, because it runs this same analysis itself, in the browser, for any q-point you ask about.
`tools/make_fluorite_bands.py` regenerates the example file (needs phonopy).

## What each step does

1. **Checks** (`checks.py`). File exists/not empty, whether it carries symmetry operations; element symbols,
   singular/skewed cell, overlapping or very close atoms; the parent's symmetry at several tolerances (warns when it
   gains symmetry at a larger tolerance, i.e. the coordinates are off-symmetry, or is P1); atom counts and
   composition of the pair; after the comparison: large displacement or strain, strain the child's own symmetry
   forbids, child **not a subgroup** of the parent (error), amplitude hidden in skipped stars, unexplained
   remainder, ambiguous or missing labels. `--verbose` shows informational findings, `--strict` turns any warning
   into exit status 2, errors give status 1.
2. **Symmetrise** (`symmetrize.py`). pymatgen's `SpacegroupAnalyzer` runs in the pymatgen interpreter at several
   tolerances; with `--symprec auto` (default) the one with the highest symmetry up to 0.1 A is used and
   reported. The symmetry is assigned **in your own setting and origin**: the positions are averaged over the
   operations in place and written as `<name>_symmetrized.cif` with explicit operations. (`standardize=True` in
   the API returns pymatgen's refined standard-setting cell instead, but that moves the origin, which changes
   the +/- of irrep labels.)
3. **Space group** (`spacegroup.py`). The 230 groups come from `tables/space_groups.json` (above). A
   structure's operations are matched to one of them by an affine search (basis change `P`, origin `p`) using
   rotations, origin-independent screw/glide parts and an exact Smith-normal-form origin solve. No spglib is
   involved. All 230 groups are recovered from random cells and origins in the tests.
4. **Cell relation, atom matching, modes, strain** (`compare.py`, `modes.py`). Integer supercell from lattice
   metrics, origin and atom correspondence, all wavevectors of the child supercell grouped into stars, each
   decomposed into real irreps; strain from the polar decomposition.
5. **Labels** (`labels.py`), described next.

## Irrep labels: how, and where they can be ambiguous

The ISOTROPY tables give, for every parent space group and irrep label, the isotropy subgroups (child space
group numbers) and their number of free parameters. For each irrep found here the same fingerprint is computed
(each isotropy subgroup is identified with `spacegroup.identify`) and looked up. When the irrep has inversion
parity at the standard origin, parity separates labels that otherwise share a fingerprint (R4+ vs R5-).

* A label is reported only if its fingerprint matches; if two or more labels match, **all are listed**
  (`M2+/M3+`) and a note is added. Nothing is guessed.
* In the cubic perovskite this gives R4+ (tilts), R4-, R5+, R1+, R3+ at R; X1+, X3-, X4-, X5+, X5- at X; GM4-,
  GM5- at Gamma; and M5+, M5- at M. At M a few same-parity irreps stay ambiguous (M2+/M3+, M1+/M4+).
* **The +/- depends on the origin.** Labels refer to the standard origin of the parent group (as in ISOTROPY). The origin
  used is the equivalent standard origin *nearest to your coordinates*, and the report prints where it is (and
  which atom sits there). Putting the A site at the origin instead of the B site swaps R4+ for R5- in the
  perovskite; a test checks exactly this. Use the origin you intend.
* Child space-group symbols use the default International Tables setting (origin choice 2 where there are two).

## Conventions

* **k** is in fractional coordinates of the reciprocal basis of the (primitive) cell you pass in; `compare` finds
  the supercell's k-points itself. `ModeAnalysis` requires a primitive cell (`to_primitive`, or `--primitive`).
* **Amplitude** = root-sum-square displacement (A) over the child supercell, measured on the undeformed parent
  lattice; squared amplitudes of all modes add up to the squared total displacement.
* Strain is `U - I` from `F = R U`, in the parent's Cartesian axes. The origin is chosen so the net displacement is
  zero.

## Data tables

| file in `distortkit/tables/` | what | where it comes from |
|---|---|---|
| `space_groups.json` | the 230 space groups, International Tables default settings | spglib's database (BSD-3), via `tools/build_tables.py` |
| `wyckoff.json` | all 1731 Wyckoff positions with their letters | computed from the group operations by `tools/build_tables.py`; letters from spglib |
| `data_isotropy.txt`, `data_irreps.txt` | irrep labels (X5+, R4+ ...) | ISOTROPY Software Suite (Stokes, Hatch, Campbell, BYU); unmodified; **please cite it** |

`tools/verify_tables.py /path/to/iso` compares the two JSON tables with ISOTROPY's `data_space.txt` and `data_wyckoff.txt`
(not distributed here): all 230 operation sets are identical and all 1731 Wyckoff positions are the same special positions,
once ISOTROPY's different conventions for them are converted (it writes templates of centred groups in the primitive cell
and, for monoclinic groups, with another unique axis). Letters of special positions in a structure are conventional up to the
origin and basis choice of the group's normaliser (e.g. which axis of P2 is `1a`); DistortKit follows spglib/International Tables.
To use another copy of the label tables set `ISODATA=/path/to/tables`.

## Limits

* The child must be an *integer supercell* of the parent's primitive cell with the same atoms (no vacancies,
  substitutions or partial occupancy). Occupancy and magnetic (moment) modes are not implemented.
* CIF input needs explicit symmetry operations; a CIF with only a space-group symbol is rejected.
* Irrep labels can be ambiguous (above) and exist only for irreps whose isotropy fingerprint is in the tables
  (special k-points and lines).
* Large supercells: stars below `min_star_amp` (2e-3 A) are not decomposed and are reported as a combined
  number; stars needing a supercell above 16 cells are only analysed above 0.02 A. A genuinely significant
  star with a large supercell is slow (`--fast`). A 12-dimensional irrep at k=(0,1/4,0) of the fluorite parent
  (8-cell supercell) does decompose (about a minute for the HfO2 Pbca comparison); the same irrep type at k=(1/4,0,0)
  of the cubic perovskite (64-cell supercell) was not confirmed to finish.
* `relate --common` finds parents by pseudo-symmetry up to about 0.5 A (see above); larger distortions need `--parent`.
  A common parent is only searched for among structures with the same atoms; reconstructive pairs are not handled.
* `invariants` works on the modes found in the analysis (not on a bare parent + irrep), reports terms by multidegree
  rather than as explicit polynomials in a standard basis, and does not include strain or gradient terms.
* Irrep labels in the side-by-side table depend on the origin of the parent that was chosen (+/- and R4+ vs R5-).
* Space-group identification needs an operation set that really is a group: for an off-symmetry structure it
  stops with that reason (raise the tolerance or symmetrise first) instead of guessing.

## Tests

```bash
python3 -m unittest discover -s tests                     # about 2.5 min
DISTORTKIT_SLOW=1 python3 -m unittest discover -s tests   # also all 230 space groups, a 64-cell k-point, the HfO2 common-parent table
```

They include independent-geometry checks (a rigid octahedron rotation built from plain geometry), all six
isotropy subgroups of the tilt irrep, the invariants against the Molien formula, the 230 space groups and 1731 Wyckoff
positions, pymatgen and built-in symmetrisation, the POSCAR-without-symmetry pipeline, and the CLI. Tests that need
pymatgen or spglib skip themselves if no interpreter with it is found.

The web viewer has its own tests, which need only Node.js: `node --test viewer/tests/viewer.test.mjs`.
